# Open Decisions

Status: Living document (created 2026-08-09)
Role: decisions deliberately **not** made in this architecture pass — each with why it can wait, the trigger that forces it, and a recommended default so the coding agent is never blocked. Rule: if a phase reaches an open decision and the user is unavailable, build the recommended default; none of these defaults require rework to replace later (that property is what qualified them to stay open).

Everything else in `docs/architecture/` is decided. If something feels undecided and is not on this list, that is a documentation bug — raise it, don't improvise.

| OD-01 | **Units: kg-only vs. lb support** | User trains in kg; lb support is pure speculation. But it touches display formatting, `loadStepKg` semantics, and plate math if ever added. | Only if a real lb need appears (e.g., traveling gyms). | Kg-only everywhere in MVP. Value unproven for this user. | During Phase 3 UX polish, after real gym use of the logging flow. | Ship without. | OD-07 | **Azure region/SKU tuning / self-host exit** | Azure App Service B1 + Flexible Server B1ms in West Europe (ADR-009) satisfies current needs at ≈ €25–30/month; a VPS self-host exit exists via `pg_dump` restore + `next start` behind Caddy. | OD-08 | **Training-day reminders (Web Push)** | iOS supports Web Push for installed PWAs (16.4+), but it adds a push service, subscription lifecycle, and permission UX for a single disciplined user. | Post-MVP, only if sessions are actually being forgotten. | None in MVP. | OD-09 | **Autoregulated deloads / readiness-informed recommendations** | Evidence-blocked, not preference-blocked: GAP-05 (deload dose-response untested beyond one protocol) and EVIDENCE-027 (no recovery-variable evidence) mean any auto-deload trigger would be pure invention today. | OD-10 | **Passkey login** | Clean upgrade over passwords (phishing-resistant, Face ID UX) but adds credential management + recovery flows; password + argon2id + throttling is adequate for one user now. | Post-MVP, opportunistically. | Password now. If added: passkey as an *additional* credential with password fallback retained (single-user lockout via lost passkey is the risk to design around). |
| OD-11 | **Exercise merge/dedupe tool** | Duplicates only matter once real data fragments across accidental duplicates (e.g., "DB Press" vs "Dumbbell Press"). If built: explicit two-step merge (re-point `set_logs`/prescriptions, archive loser), audit note on both records. |

## Notes

- **OD-02 and OD-03 share a philosophy:** both park a heavier mechanism (op merging; temporal tables) behind a felt pain that may never arrive, on top of a base design that loses nothing meanwhile (LWW never drops facts silently — conflicts are logged; current-convention never corrupts SetLogs — weights are reinterpretation only).
- **OD-09 is the only evidence-gated item.** Every other row is a product/engineering timing choice; OD-09 is blocked by the state of the science itself, and its resolution path runs through the evidence registry (see `evidence-to-design.md` §3.4).
- Resolved decisions move out of this file and into an ADR (new or amended), with the resolution date and trigger noted.
- **OD-06 (e1RM formula for analytics) — resolved by amendment 2026-09-05 → ADR-011.** Trigger: owner acceptance of the estimated-1RM architecture revision (`docs/reviews/estimated-1rm-load-translation-architecture-revision.md`, owner-decision addendum, O-9). It was **amended, not adopted as recorded**: Epley is kept with `f(1) = 1`; the input changes from plain `reps` to `reps + reported RIR`; the "reps ≤ 12 for display" cap becomes a source-set admissibility ceiling `RTF ≤ 12`; a new target ceiling `RTF ≤ 15` applies to translated loads; every displayed value carries a ±10 % band; the formula name becomes a versioned `algorithm` id on every DTO. The recorded default would otherwise have been built at the start of Phase 9; the tracker now ships earlier as ADR-011 Release A. OD-04 is untouched.
