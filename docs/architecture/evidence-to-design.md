# Evidence-to-Design Map

Status: Accepted (2026-08-09); row 20 added 2026-09-05 (ADR-011, owner decision O-17)
Role: the traceability layer between the evidence corpus (`docs/evidence/`) and the architecture. Every science-adjacent design decision appears here with its evidence basis, its classification in the four-tier hierarchy, and — deliberately, per row — what the evidence does **not** justify. When a future change touches one of these decisions, this file is the first thing to update.

Sources: `docs/evidence/evidence-registry-reviewed.md` (EVIDENCE-001…031 processed; **EVIDENCE-032…037 provisional** — entered 2026-09-05 outside the PDF/research-note intake, closure condition in the registry's "Verification pass 3"), `docs/evidence/product-evidence-boundaries.md` (principles A1–A16, heuristics B1–B13, preferences C1–C7; A13–A16 and B12–B13 rest on provisional items), `docs/evidence/research-gaps.md` (GAP-01…12; GAP-07's narrowing and GAP-11/12 rest on provisional items), `docs/input/rp-volume-landmarks.md` (coaching preset input, not evidence).

## 1. The four-tier hierarchy and where each tier lives in the system

These categories must never collapse into one another. Each has a distinct structural home:

| Tier | Meaning | Structural home |
|---|---|---|
| **Evidence-supported principle** | Directly backed by registry entries | Cited here and in doc rationale; shapes *what exists* (e.g., that multiple strategies exist at all). Never attached to a concrete numeric rule. |
| **Programming heuristic** | Plausible extrapolation (B1–B11), not itself tested | `classification: 'heuristic'` on shipped strategy configs; `source`/label metadata on seeded volume presets; caveat copy rules (volume-model §5). |
| **Configurable product rule** | A concrete setting the user can change | Prescription fields, strategy config JSON, deload config, landmark values, contribution weights — all editable data, none hard-coded. |
| **User-specific observation** | What this user actually logged | SetLogs, decisions, bodyweight, recovery entries — immutable facts. Never auto-promoted into rules; only read by strategies as inputs. |

Enforcement points: the `classification` enum on strategy configs has no reachable `'evidence_supported'` value for concrete triggers (ADR-006); seeded presets carry heuristic labels that the UI must render (volume-model §5); recommendation reason codes describe *behavior* ("all prescribed reps completed"), never scientific claims.

## 3. Standing rules derived from this map

1. **New science-adjacent features start here.** Before building, add the row: basis, tier, and the not-justified column. If the not-justified column would be empty, the claim is probably overreaching.
2. **The not-justified column is load-bearing.** Several MVP refusals (auto-deloads, auto-MEV/MRV, RIR correction, tempo fields) exist *because* of it; removing a refusal requires new evidence entering the registry, not a product whim.
3. **Preset/config edits never change tier.** A user tuning a heuristic default makes it `'user_defined'` — it does not become more (or less) scientific, and the UI must not imply otherwise.
4. **Corpus updates flow one way.** New papers → registry → boundaries/gaps revision → this map → design change. Design documents never cite papers directly; they cite EVIDENCE/GAP/B/C IDs so the interpretation layer stays single-sourced.
   **Temporary exception, recorded 2026-09-06 (open):** EVIDENCE-032…037 entered the registry on 2026-09-05 with a document in the design lineage — `docs/reviews/estimated-1rm-evidence-research.md`, an independent evidence review written for the estimated-1RM feature — as their provenance of record, i.e. the flow ran design lineage → registry, the inverse of this rule. The items are therefore held as **provisional** (registry §13) and are cited in row 20 only with that marker. The exception **closes** when the registry's "Verification pass 3" closure condition is met in full: PDFs under `docs/research/`, normalized notes and `Processed` inventory rows under `docs/research-notes/`, a numbered page-location re-verification pass, and the closing date written here. Until then no further item may enter the registry by this route, and no design-document tag may be lifted to `[E]` on the strength of these six items.
